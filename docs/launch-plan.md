# 轻语 TTS · 开源发布与冷启动计划

> 目标：**90 天 500 Star**（与鉴安同口径）。核心不是"发很多平台"，而是**一个能被一句话说清、三秒看懂价值的产品**。

---

## 一、发布前必须就位（Day -7 ~ Day 0）

- [ ] 仓库不含任何内部材料（竞赛方案、商业材料均在本仓库之外）。
- [ ] README 首屏三要素齐全：一句话定位、30 秒上手、真实截图或 GIF。
- [ ] 演示视频（90 秒）已录制并上传，链接放在 README 第一屏（见 `demo-video-script.md`）。
- [ ] `LICENSE` / `CONTRIBUTING.md` / `CITATION.cff` / CI 全绿。
- [ ] 一个**可直接体验的形态**：单文件 `web/轻语TTS-移动端.html` + 本地 Flask（不需要用户申请账号）。
- [ ] Topics 配置：`tts` `text-to-speech` `ssml` `wechat-miniprogram` `edge-tts` `accessibility` `chinese`。

## 二、90 天节奏

### 第 1 周：冷启动（目标 50 Star）

| 天 | 动作 | 要点 |
|---|---|---|
| D1 | 发布 v1.0.0 Release | Release Notes 写清"能干什么"，附单文件 HTML 下载 |
| D1 | 发 V2EX `分享创造` 节点 | 标题：`我做了个能把论文/笔记变成语音、锁屏也能听的小工具` |
| D2 | 发 小众软件 / 少数派 | 提交软件收录；强调"不联网也能出音频"（本地引擎兜底） |
| D3 | 发 即刻 / 小红书 | 面向健身与通勤人群，讲"听自己攒的资料"这个具体场景 |
| D4 | 发 Bilibili 演示视频 | 90 秒竖屏，前 3 秒必须是"粘贴文本 → 戴上耳机跑步" |
| D5-7 | 回复所有 Issue 与评论 | 48 小时内必回；把高频问题补进 README |

### 第 2–4 周：内容驱动（目标 150 Star）

- 写 2 篇技术文章发到掘金 / 知乎：
  1. 《我是怎么绕过 edge-tts 不支持 SSML 的》——属性注入的完整过程（含源码级依据）；
  2. 《双引擎 + 自动降级：让语音合成不再被单一云服务绑架》。
- 每篇文章末尾放仓库链接与"能直接下载的成品"。
- 参与 2 个相关 Awesome 列表的 PR（`awesome-tts`、`awesome-wechat-miniprogram`）。

### 第 2 个月：社区共建（目标 300 Star）

- 提出"**音色包**"贡献机制：社区可提交自定义 SSML 停顿模板（演讲稿 / 有声书 / 诗文）。
- 发起"**我的资料**场景征集"：收集真实使用场景，做成 gallery。
- 固定每两周一个 Release，写清 changelog。

### 第 3 个月：破圈（目标 500 Star）

- 找 3–5 位学习 / 健身 / 无障碍领域博主做真实体验（不要求好评，只要求真实）。
- 面向视障社区做一次专题分享（这是本项目社会价值的实打实的落点）。
- 把"离线朗读（Web Speech API）"做成独立可嵌入的组件，方便他人复用。

## 三、容易被忽略但决定 Star 的三件事

1. **首屏不要放架构图**。Star 的人多半只想确认"这玩意儿能不能解决我的问题"。架构图放后面。
2. **给出"不用读文档就能用"的路径**。本项目的最强钩子是"下载一个 HTML 文件，传到手机，点开就能用"。
3. **如实写限制**。README 第五节已列 7 条已知限制——不藏限制反而更可信，也减少无效 Issue。

---

## 四、不做的推广

- 不刷 Star、不买榜（会被 GitHub 识别且损害项目信誉）；
- 不在无关社群硬广；
- 不公开任何用户的真实文本与音频。
